Артём Смирнов
Java-разработчик · Краснодар · открыт к предложениям

Десять лет в промышленной автоматизации: четыре года программировал контроллеры (Siemens, Schneider Electric, Allen Bradley) и разрабатывал операторские интерфейсы SCADA, затем руководил отделом АСУ ТП, последние три года — проектами и командой разработчиков.

Перешёл в backend-разработку осознанно. В автоматизации я упёрся в потолок: языки контроллеров закрыты вендором, вокруг них нет ни нормального тестирования, ни версионирования, ни библиотек. Java выбрал за строгость — после производства, где ошибка останавливает линию, мне важно, чтобы её ловил компилятор, а не прод — и за зрелость инструментов для долгоживущих серверных систем.

Выбор проверил делом: взял реальную задачу предпринимателя и довёл её до сервиса, который работает в проде круглосуточно и за который платят. Больше всего интересны интеграционные задачи — когда сервис живёт не сам по себе, а разговаривает с чужими системами и обязан переживать их отказы.

Проекты
РегДозор — коммерческий сервис
Интеграционный сервис мониторинга обязательной маркировки «Честный знак» для заказчика — индивидуального предпринимателя, торгующего на маркетплейсе. Работает в проде круглосуточно, единственный разработчик — от постановки задачи до деплоя и поддержки.

Забирает данные из внешних систем — сайта оператора маркировки, официального API публикации правовых актов, правовой базы и Telegram Bot API, — сверяет коды ТН ВЭД и ОКПД2 с номенклатурой заказчика и присылает разбор: какой товар затронут, какая обязанность возникает и с какой даты, какая статья КоАП её обеспечивает и какой штраф грозит его правовой форме.

Java 21 без фреймворков, 61 класс, две внешние зависимости. Интересное внутри: гарантия доставки «хотя бы один раз», сторож источников против тихого отказа парсеров, экранирование текста, пришедшего из чужой системы.

Java 21 jsoup Jackson Telegram Bot API Maven ScheduledExecutorService

Explore With Me — афиша событий
Два самостоятельных микросервиса со своими базами: основной сервис и сервис статистики. Около 35 эндпоинтов, разнесённых по публичному, приватному и административному контуру, межсервисное взаимодействие по REST через общий модуль DTO, развёртывание Docker Compose на четыре контейнера. Поиск событий по радиусу от локации считается ортодромической формулой прямо в SQL, поэтому фильтрация не поднимает лишние строки в приложение.

Spring Boot Spring Data JPA Hibernate PostgreSQL 16 Docker Compose многомодульный Maven

ShareIt — сервис аренды вещей
Разделён на шлюз и сервер: шлюз валидирует запросы, сервер держит бизнес-логику и работу с базой. Так сервер не тратит ресурсы на разбор заведомо некорректных запросов, а правила валидации меняются без его пересборки. Бронирования со статусами, отзывы после аренды, запросы на вещи, которых пока нет в сервисе.

Spring Boot Spring Data JPA PostgreSQL Docker JUnit 5 MockMvc Checkstyle SpotBugs JaCoCo

Filmorate — сервис оценки фильмов
Схема базы из восьми таблиц с вынесенными справочниками и ER-диаграммой, рукописный SQL через JdbcTemplate, доступ к данным за интерфейсами хранилищ — благодаря этому замена хранилища в памяти на СУБД прошла без изменений в сервисном слое. Групповую версию проекта делал командой из трёх человек через feature-ветки и pull request'ы.

Spring Boot JdbcTemplate SQL H2

Warhammer 40k — движок правил настольной игры
Пет-проект на чистой Java: полная последовательность боя и менеджер фаз хода, 51 класс. Движок не знает о конкретных правилах — они подключаются через интерфейс с хуками, а урон описан интерфейсом с двумя реализациями, фиксированной и бросковой. Новое правило добавляется без правки боевого ядра.
